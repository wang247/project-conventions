# project-conventions

**项目编码约定生成器**：一个完全自包含、可移植的 Agent Skill。AI 通过逐领域追问与你对齐编码偏好，最终在仓库根目录生成一份单文件中文 `AGENTS.md`，作为所有 AI 编码代理（Claude Code / Codex / Cursor / zcode / deepseek harness 等）共同遵守的项目约定。

学习Matt Pocock的grill-me和gril-with-docs思想，将约束和grill更加具体化，着重grill界面、交互、后端与架构、数据与 API 契约、健壮性、安全、测试策略、工程规范方面。

一句话：**把约束变成文件，把决策留给拷问，让每个 agent 第一次就写对。**

## 它解决什么问题

AI 编码（vibe coding）有三个反复发生的失败模式：

| 失败模式 | 具体表现 |
|---|---|
| **AI 自由发挥** | 不立规矩，AI 每次的实现方式都不一样：这次用 fetch 下次用 axios，这次集中校验下次散落各处，这次终于写对下次又忘 |
| **规矩靠嘴传** | 每个新会话都要重新口头交代规矩：交代了费上下文，忘了就翻车，换个 agent（Claude Code → zcode → deepseek）一切归零 |
| **文档腐化**（最致命） | 项目有了 SPEC / 设计文档，但需求一变文档还停在上一版——AI 读着**过时的文档**理直气壮地写出错的代码，比没有文档更糟 |

本技能的解法：**把规矩一次性谈判定稿成 `AGENTS.md`**（终结自由发挥和口头交代），并内置一套**随需求变更强制同步的文档体系**（终结文档腐化）。此后任何 agent 读仓库里的文件，就知道规矩、路标和流程。

## 核心特性

### 1. 文档体系是重中之重

对 AI 编码而言，**文档就是 agent 的上下文与记忆**——文档乱了，代码必乱。本技能引导建立完整的四层文档结构：

```
/
├── AGENTS.md     # 薄入口：约定 + 三张地图 + 工作流程（每次会话必读）
├── CONTEXT.md    # 术语表：领域概念的统一定义，禁止 AI 自行揣测
└── docs/
    ├── specs/    # 演进层：功能需求 + 可判定验收标准，按功能拆文件
    ├── design/   # 稳定层：概要设计 / 架构，变更走 ADR
    ├── adr/      # 历史层：架构决策记录，只追加、不改旧
    └── manual/   # 人类层：面向最终用户的操作手册
```

配合内嵌 `AGENTS.md` 的**三张路由式地图**，agent 拿到任务后按图索骥、按需加载，上下文永远只装当前任务需要的文档：

| 地图 | 管什么 |
|---|---|
| 文档地图 | 写/改某功能前必读哪份 SPEC，决策记录在哪 |
| 代码地图 | 入口文件、目录路由规则（新代码放哪）、关键数据流主线、外部集成点 |
| 测试地图 | 测试位置与命名、运行命令三件套（单测 / 全量+lint / typecheck）、fixture 位置、补测时机 |

地图**只写规则和入口，不枚举文件清单**——文件清单两周就变成谎言，规则不会；文件现状让 agent 现场扫描。

### 2. 需求变更时，文档更新与同步优先（强制纪律）

这是防"文档腐化"的核心机制，写死在生成的 `AGENTS.md` 里，对所有 agent 生效：

- **变更与新建走同一入口**：需求变更不许口头"把 X 改成 Y"直接改代码，必须先拷问定稿、更新文档，再动代码
- **收尾前五项一致性自检，未完成不得交付**：受影响的 SPEC 更新了吗 → 新术语进 CONTEXT.md 了吗 → 被推翻的决策追加 ADR 了吗 → 约定本身要修订吗 → 地图要更新吗
- **ADR 只追加不改旧**：决策被推翻就写新 ADR 标注 `superseded by ADR-NNNN`，保留决策历史——防止半年后新会话的 agent 不知道你们否决过什么，又"好心"建议一遍
- **SPEC 按功能拆文件**（`docs/specs/{功能名}.md`）：变更只动受影响文件，不维护一份牵一发动全身的巨型 SPEC

### 3. 生成器，不是资料库
技能不内置一套写死的约定，而是一个**谈判流程**：AI 按领域展示有主见的默认约定，你逐批确认（每轮回复"全收 / 改第 N 条 / 补充"即可），定稿零 "it depends"。

### 4. 八大领域，条条有立场
界面、交互、后端与架构、数据与 API 契约、健壮性、安全、测试策略、工程规范。每条默认约定都具体可执行，例如：

- 客户端校验只为即时体验，最终以服务端校验为准
- 异步按钮 loading 必须在 `finally` 中重置，禁止任何路径卡死
- 禁止"仅改本地状态不调接口"的假保存
- SQL 一律参数化，密钥绝不进前端代码
- 独立异步操作必须 `Promise.all` 并行（React 栈附加包）

### 5. 内置六阶段工作流程
`AGENTS.md` 自动带工作流程章节，六个阶段一条箭头走到底，需求变更则回到起点闭环：

```mermaid
flowchart TD
    A["阶段 0 · 约定先行<br/>project-conventions 生成 AGENTS.md"] --> B["阶段 1 · 需求拷问<br/>逐分支问透设计树，不留 it depends"]
    B --> C["阶段 2 · 规格化<br/>写 docs/specs/{功能}.md<br/>必须带可判定验证标准"]
    C --> D["阶段 3 · 架构确认<br/>数据模型 / API / 组件树<br/>人工过审前不写码"]
    D --> E["阶段 4 · 微步实现<br/>一次一个组件，小步提交"]
    E --> F["阶段 5 · 评审<br/>代码评审 + 安全自检<br/>+ 交互自检"]
    F --> G["阶段 6 · 收尾<br/>文档同步五项自检<br/>关键路径人工终审"]
    G --> H([交付 ✅])

    X["⚠️ 需求变更"] -.->|重新走同一入口| B
    G -.->|"SPEC / CONTEXT / ADR<br/>未同步则打回"| E
```

### 6. 栈附加包机制
React/Next.js 性能铁律、复杂业务后端 DDD 铁律等，仅在技术栈命中时注入，避免约定膨胀。

### 7. 双模式
- **新项目**：问清技术栈后逐领域开问
- **现有项目**：先扫代码库，按现状提议约定，冲突项单独标注；已有 `AGENTS.md` 时走增量更新，不覆盖你的自定义内容

### 8. 完全可移植
**单个自包含 `SKILL.md`**，零平台专属工具、零绝对路径，只依赖"读写文件 + 对话"。

## 安装

### Claude Code / 任何支持 skills 的 agent

把整个文件夹（其实只有一个 `SKILL.md`）拷入技能目录：

```bash
# Claude Code
cp SKILL.md ~/.claude/skills/project-conventions/SKILL.md

# 或任意 agent 的 skills 目录
cp SKILL.md <agent-skills-dir>/project-conventions/SKILL.md
```

### 不支持 skills 的 agent

把 `SKILL.md` 正文整段贴进系统提示词即可，流程照跑。

### WorkBuddy

放入 `~/.workbuddy/skills/project-conventions/`，新会话说 **"给这个项目建 AI 约定"** 即触发。

## 使用

1. 在项目根目录启动 agent，触发技能
2. 告知技术栈（或让它扫描现有代码）
3. 按 8 轮逐领域确认默认约定
4. 得到仓库根目录的 `AGENTS.md`，从此每个 agent 开场一句：**"先读 AGENTS.md，然后我们做 XX"**

## 生成的 AGENTS.md 结构

```
# {项目名} 编码约定
## 1. 界面        ## 5. 健壮性
## 2. 交互        ## 6. 安全
## 3. 后端与架构   ## 7. 测试策略
## 4. 数据与 API 契约 ## 8. 工程规范
## 文档地图 / 代码地图 / 测试地图
## 工作流程（六阶段）
## 文档同步（需求变更时强制执行）
## 附：个性化说明
```

配套的仓库文档结构见「核心特性 → 1. 文档体系是重中之重」。

## 设计原则

- **路由式，不写清单**：地图只写规则与入口，文件枚举交给 agent 现场扫描
- **薄 AGENTS.md**：约定文件每次会话都被读，按"不写这条 AI 会犯错吗"的标准取舍
- **内嵌优先，超限才拆**：地图单节超 30 行才拆到 `docs/maps/`
- **零依赖**：不要求任何 MCP、插件或特定运行时
